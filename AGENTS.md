# QADREN — правила для AI-агентов и Codex

Этот файл — начальная точка контекста для любого агента, меняющего QADREN.

## Перед работой

1. Прочитать `README.md`, `docs/README.md` и **`docs/architecture/backup-model.md`**; для задач реализации — `docs/roadmap.md`.
2. Прочитать профильные документы в `docs/architecture/`, `docs/policies/`.
3. Проверить `docs/decisions/README.md`, `docs/architecture/technology-stack.md` и `docs/development/engineering-rules.md`.
4. Сформулировать границы задачи, что уже утверждено, что остаётся неподтверждённым, какие тесты нужны.

## Не нарушать

- Rust — кроссплатформенное ядро; SwiftUI — нативный macOS UI; Swift/Apple APIs — iCloud Documents adapter.
- UI, платформа и адаптер не должны захватывать общую бизнес-логику.
- Не вводить обязательные внешние runtimes конечному пользователю.
- Соблюдать D-016: один adapter/provider поддерживает множество независимых StorageConnection; никогда не возвращать singleton Keychain `default`, не ограничивать по внешнему account ID. OAuth/Keychain состояние принадлежит `connection_id`.
- Секреты никогда не сохранять в SQLite, Git, логах, адресах HTTP; Client ID — публичная конфигурация сборки, Client Secret — не часть настольного приложения.
- Любые операции Remove/Disconnect меняют только локальные соединения и их полномочия; ни один такой UI action не вправе удалять объекты в облаке.
- QADREN не инициирует скачивание содержимого на основной MacBook без предварительного согласования; не вмешивается в iCloud/macOS и другие приложения.
- Делегированный job выполняет только Worker; Controller мониторит отчёт.
- В текущем релизе **нет собственного версионирования содержимого**. Защищать от опасных удалений/перезаписей, сохранять служебную историю синхронизации; BackupSet — только в истории Git и будущем ADR.
- Первый релиз — полноценная **локальная** версия; удалённые Worker и межузловой протокол — следующий этап и отдельное решение.
- `Scenario` описывает правила синхронизации, `Job` — конкретное исполнение и разовые файловые операции; не создавать постоянный сценарий при ручном копировании.
- iCloud Documents ограничен собственным контейнером; Local Filesystem — отдельный адаптер.
- Не реализовывать зависимости между сценариями в текущей версии.
- Не имитировать готовность API/Apple entitlements без тестов.

## Изменение и проверка

Работать небольшими проверяемыми патчами. Обновлять документацию вместе с кодом. Проверять форматирование, тесты, ошибки, security review и сборку; в результате перечислять реально исполненные проверки и известные ограничения. Никогда не помечать планируемую проверку как прошедшую.

Полные правила: [разработка](docs/development/engineering-rules.md), [тесты](docs/development/testing-and-quality.md), [сборки](docs/development/build-and-release.md).


## Release 1: обязательный маршрут Codex (2026-10-11)

Перед любой задачей прочитать актуальные Issue #12 и соответствующую дочернюю Issue, затем `docs/roadmap.md`, `docs/architecture/overview.md`, `docs/development/release-1-validation.md` и профильные политики. Сначала проверить реализованные методы, тесты, SQLite migrations и FFI; не создавать дубликаты модулей. Факты на конкретном SHA отделять от планов и непроверенных утверждений.

**Согласованная граница:** первый исполнитель вызывается из процесса SwiftUI, но логика исполнения, переходы Job, persistence и reconciliation принадлежат Rust Core. SwiftUI не становится Job Engine. Отдельная фоновая служба вводится позднее, без второго движка. Закрытие UI на первом этапе может останавливать исполнение, но НЕ должно превращать неизвестный результат в неуспех, забывать attempt или повторять effect. Для полноценного Release 1 закрытие UI не должно останавливать выполнение — этот gate сохраняется.

**Перед реализацией:** зафиксировать входы/выходы операции, возможные эффекты, capability/consent, durable state до I/O, verification/reconciliation, fault points, platform scope и acceptance. Не начинать destructive-операции без доказанного механизма защиты от конкурентных изменений. Любое неподтверждённое разрешение — fail-closed. Конкретное согласие на QADREN-инициированную загрузку на главный MacBook проверять перед I/O, не выводить из capability или общего UI toggle.

**Выполнение:** реализовать вертикальный функциональный срез в пределах Issue; отдельно проверять mock, native platform и настоящие интеграции. Сначала mock/интеграционный путь создания нового файла без overwrite через JobStore → adapter → verification → durable result → UI. Существующие `jobs.rs`, `confirmation.rs`, `verification.rs`, `registry.rs` использовать повторно. Секреты в SQLite/логах запрещены. Отдельные библиотеки/слои — только при обоснованной необходимости.

**Перед публикацией прямо в main:** проверить diff и область изменений; запустить `bash scripts/test-core.sh` и применимые Swift/FFI/adapter tests; провести code review (инварианты, владелец состояния, миграции, гонки, обратная совместимость) и security review (пути, symlink/hardlink, overwrite/delete, OAuth, consent, unknown/retries, partial effects). Если проверки недоступны — явно указать их как НЕ выполненные; это не подтверждение DoD. Зафиксировать SHA, команды, результаты, ограничения и ссылку на Issue. Не делать PR/ветки обязательными и не требовать подтверждения пользователя для каждого малого патча; объединять изменения по законченному результату.


## Совместимость с AI-Docs-Hub и независимость от точки входа

**Обязательная политика для всех исполнителей:** обычный ChatGPT-чат, Codex CLI/агент, AI-Docs-Hub MCP, локальный разработчик и будущие инструменты следуют одним и тем же правилам QADREN. Способ подключения не меняет архитектурных решений и Definition of Done.

**Источники истины и приоритет:**
1. Явно согласованные решения владельца проекта и обязательные политики QADREN (`docs/policies/`, действующие ADR в `docs/decisions/`).
2. Действующие продуктовые и модульные контракты (`docs/architecture/`) и проверенный исходный код текущего `main`. При расхождении кода и документации фиксировать дефект/несогласованность, а не молча объявлять один из них правильным.
3. Этот `AGENTS.md`, `docs/development/`, `docs/roadmap.md` и соответствующая GitHub Issue.
4. AI-Docs-Hub: **инструменты маршрутизации, индексирования и качества**, а не альтернативный владелец продуктовой архитектуры. Его managed instruction block может уточнять вызовы инструментов, но не переопределять пункты выше.

**Безопасное подключение:** сначала выполнить AI-Docs-Hub onboarding и scaffold в dry-run; проверить `git diff`, список планируемых файлов, настройки docs include/exclude, namespace и секреты. Затем разрешить только осознанные изменения. Существующие непустые `AGENTS.md`, `docs/`, ADR и политики нельзя заменять шаблонами, перемещать, дублировать в параллельных каталогах или автоматически переписывать. Уникальные project rules остаются в QADREN. Добавленный Hub managed block должен быть узким, ограниченным своими маркерами и обратимым; вне этих маркеров содержимое AGENTS неприкосновенно.

**Инварианты автономности:** работа, сборка, локальные проверки и чтение документации QADREN должны быть возможны без установленного/запущенного AI-Docs-Hub; отсутствие Hub не меняет критерии приёмки и не блокирует исправления. Не импортировать Hub как runtime-зависимость Rust/Swift и не хранить secrets/токены проекта в его документации, индексах или логах.

**Единый жизненный цикл:** независимо от точки входа сначала inventory кода и контекста, затем scope/acceptance, implementation, Rust/Swift/FFI/adapter tests, code review, security review, прямой commit в `main` и evidence в Issue. При наличии AI-Docs-Hub можно использовать его индекс, project-context freshness, verification и review gates как дополнительные проверки. Не выдавать результат индекса или статус инструмента за доказательство выполнения тестов. Отсутствующий Hub/review tool помечать как unavailable и проводить доступные эквивалентные проверки самостоятельно, без фиктивных PASS.

**Запрещено:** автоматически запускать scaffold с записью, принудительное `/init` с перегенерацией проекта, создавать дополнительный `AGENTS.md` как альтернативный root-policy, менять архитектуру по общему Hub template, автоматически делать commit/push в обход review или передавать содержимое QADREN внешним индексаторам без разрешённой конфигурации. При конфликте инструкций остановить только соответствующее изменение и предложить явное разрешение конфликта, остальную независимую работу продолжать.
