# QADREN — визуальный язык, бренд и токены

## 1. Художественный принцип

**Cyberpunk Control Surface**: интерфейс технического диспетчера с современной нативной механикой macOS. Это не «игровой HUD»: содержимое читается часами; декоративные световые контуры не должны конкурировать с данными. Сильнее выделяются активные операции, выбранный фокус и блокирующие события. Меньше внимания получают успешные и исторические события. Никакого постоянного искусственного мерцания или «сканирующих» линий.

Содержимое рабочего окна занимает максимум площади. НЕТ гигантских hero-заголовков, широких пустых полей, постоянной правой палитры, бокового меню в мониторинге, декоративных диаграмм. Одна шапка + адаптивная сетка + узкая строка состояния. macOS titlebar/traffic lights сохраняются нативными.

## 2. Бренд — строго из репозитория

Канонический графический ресурс: **`assets/qadren-logo.png`** (192×192 PNG, прозрачный фон, существующий голубой/синий знак). В SwiftUI — загрузка asset catalog image из **этого файла без перерисовки**, для HTML-прототипа — `../../assets/qadren-logo.png`. Он использован в README проекта. Не добавлять другой брендовый символ, не делать SVG-«реплику» и не искажать исходные пропорции.

- Типовые размеры: 20 pt рядом с названием в compact menu; 24–28 pt в titlebar/шапке; 48–64 pt только для экрана приветствия/пустой конфигурации.
- Отступ вокруг знака: не меньше 1/8 видимой ширины, сохранять aspect ratio, без обрезки и clipping.
- Тёмная и светлая темы используют тот же файл; при проблеме контраста меняется подложка/отступ, **не цвета логотипа**.
- Название «QADREN» — обычный текст SF Pro Semibold, без произвольного декоративного шрифта и слоганов («SYNC WHAT MATTERS» не утверждён брендбуком).
- Системный MenuBarExtra может использовать SF Symbol в template rendering, если цветной логотип там нечитаем. Это **системный индикатор**, а не изменение брендового логотипа в окнах.

## 3. Источник численных значений

Машиночитаемая таблица — [tokens.json](tokens.json). Ниже — семантика; не копировать значения из случайной сгенерированной иллюстрации.

| Группа | Назначение |
|---|---|
| canvas, panel, raised, overlay | глубина слоёв, не стек непрозрачных карточек |
| stroke, strokeHover, focus | граница 1 pt и акцент выбранного элемента |
| brandCyan, brandBlue | действия, прогресс и навигационный акцент, визуально совместимые с логотипом |
| success, warning, danger, unknown, neutral | строго семантические состояния |
| textPrimary, textSecondary, textDisabled | иерархия без падения читаемости |
| grid, gap, inset, header, corner | общее ритмическое пространство |
| compact, regular, expanded | плотность **содержимого**, а не масштаб всего окна |

Основная тёмная палитра — практически чёрный с синим подтоном, слои тёмно-синие. Основной акцент электрический циан `#0CB9F2`, дополнительный синий `#2A80FF`. Красный — только для опасности/ошибок, янтарный — решения пользователя, сиренево-серый — неопределённость; зелёный — лишь для проверенного соответствующего статуса. Не заменять всё зелёным при `Worker report` без evidence.

## 4. Геометрия и сетка

- Базовый layout unit **4 pt**, наиболее употребимые интервалы 4/8/12/16/24.
- Отступ по краю полотна 12 pt, промежутки между виджетами 10 pt, padding виджета 12 pt, заголовок 32 pt. Системный titlebar — нативный.
- Каркас виджета: скругление 8 pt, тонкая граница 1 pt, без постоянных объёмных теней. Контролы 6 pt; маленькие pill метки 4–6 pt.
- Между строками плотной таблицы 4–6 pt, высота строки 28/34/42 pt по плотности. Нельзя уменьшать tap targets на touch-device предположениями; для macOS pointer минимальная разумная цель 24×24 pt, доступный hit area предпочтительно 28–32 pt.
- Не делать острую «схемотехническую» рамку у каждого элемента: максимум одна тонкая линия/небольшой срез угла у **ключевых** акцентных состояний, только если не влияет на clipping или accessibility.

## 5. Типографика, числа, длинные пути

SF Pro Text через системный SwiftUI font. Шкала в tokens: интерфейс 13 pt regular; widget header 13 pt semibold; secondary 11–12 pt; метрики 20 pt semibold; заголовок inspector 16 pt semibold. Технические ID и структурированные даты — SF Mono, числовые показатели — monospacedDigit(). Не применять monospaced ко всем заголовкам.

Правило переполнения: имя может усекаться в компактном превью, **полный путь обязателен** в контексте (tooltip, inspector, copy) и при детальном представлении. Запрещено показывать частичный путь как полный. Размеры и скорости с единицами, квоты со статусом источника/времени; «—» для неизвестного, не «0».

## 6. Свечение и движение

- Эффекты `glowIdle=0`, `glowFocus` ограниченный внешний контур <= 3 pt blur; для warning/danger возможна подсветка края без заливки всего виджета.
- Никаких бесконечных анимированных декоративных пульсаций. Для неопределённого прогресса — системный индикатор, при `Reduce Motion` неподвижная замена.
- Hover: 100–150 ms, focus: системный keyboard focus видим всегда, открытие инспектора максимум 160–200 ms или без анимации.
- Обновления данных не сбрасывают scroll, selection и фокус, не дёргают размер карточки. Никаких случайных «цифровых шумов».

## 7. Темы, контраст, доступность

Поддержка `dark`, `light`, `system`. Тёмная тема baseline; светлая — отдельные явно определённые semantic tokens из JSON, не CSS invert. Токены должны учитывать системные High Contrast, Reduce Transparency, Reduce Motion, Dynamic Type, VoiceOver и клавиатуру. Минимальный контраст обычного текста 4.5:1, крупного текста 3:1; если конкретная пара цветов не проходит — корректировать цвета реализации и задокументировать отличие. Пиктограмма + короткая подпись обязательны у опасных статусов; цвет и свечение **не** являются единственным сигналом.

## 8. Иконография и графики

Использовать SF Symbols с единым размером 13–15 pt и предсказуемыми именами. Облачные бренды в connection rows — только при наличии лицензированного ассета или нейтральный символ. Кольцевые шкалы, графики и сеточные диаграммы показывать **только** для измеряемых данных; если нет истории метрик, не рисовать фиктивную линию «CPU за 24 часа». ETA и общую скорость Worker не придумывать. Tooltip содержит смысл, единицы, источник данных и свежесть. Диаграмма — инструмент, не декорация.
