# QADREN — окно мониторинга (Control Surface)

## 1. Назначение и точка входа

Главное окно — **рабочее полотно из виджетов**, которое пользователь настраивает один раз и затем наблюдает без переходов между разделами. Оно НЕ является отдельными страницами «Обзор/Очередь/Файлы/История» и НЕ имеет постоянного Sidebar.

Существующие точки входа `QADRENApp.swift`: `WindowGroup("QADREN", id: "monitoring")`, MenuBarExtra → «Панель мониторинга» / «Новая рабочая панель». Сохранять поддержку нескольких окон с независимым `panelID` и конфигурациями. При повторном открытии не создавать случайных дубликатов по умолчанию: действие «Открыть» активирует существующее основное, «Новая» добавляет отдельную панель с новым ID. Технический способ управления instances SwiftUI выбрать после inventory.

## 2. Три горизонтальные зоны

1. **Native titlebar/toolbar**: traffic lights, настоящий logo asset (20–24pt) + название панели, компактное здоровье системы, глобальные фильтры popover, кнопка компоновки и контекстные действия. Не вставлять 80px-«баннер».
2. **Полотно**: scrollable adaptive grid без sidebar. Все типы виджетов живут здесь. Навигация — контекст внутри виджета, inspector или временное отдельное окно.
3. **Status bar**: одна строка, локальный Worker, статус службы, последнее обновление, число нерешённых critical. Значения с provenance/freshness. Не имитировать «работает в фоне», пока lifecycle не завершён.

### Схема композиции (структура, не размерные пиксели)

| 12-column wide (условные области) | Содержание |
|---|---|
| Первый ряд: 3 + 5 + 2 + 2 | Система · Активные задания · Очередь · Требует внимания |
| Второй: 4 + 4 + 4 | Подключения · Ресурсы Worker · Ближайшие запуски |
| Третий: 4 + 4 + 4 | События · Сценарии · Опциональная активность файлов |
| Нижняя узкая строка | Worker · служба · обновление · глобальные проблемы |

Это **дефолт пользователя без сохранённой раскладки**, не закреплённая навсегда схема. Пользователь может убирать/менять размеры, повторять тип только в другом dashboard. При узком окне deterministic reflow, не горизонтальная прокрутка всего полотна. Не рисовать «файловую активность» без реальных агрегатов.

## 3. Визуальная иерархия

Приоритет от первого к последнему: (1) блокирующие consent/conflict/UNKNOWN и ошибки; (2) текущие операции и progress; (3) доступность подключений; (4) очередь и будущие старты; (5) история и диагностические метрики. Не превращать «SUCCESS» в огромную зеленую карточку. Панель может быть полностью спокойной при нулевой активности.

**Cyberpunk** реализуется тонкими линиями/циановым фокусом, неоновой акцентной кромкой у выбранного/активного состояния, аккуратными маркерами, технической точностью; графический фон не мешает чтению. При фокусировке виджета соседние не становятся автоматически тусклыми.

## 4. Взаимодействия — без переключения экранов

- Нажатие на Job row → `JobInspector` overlay или отдельное окно с Job ID, сценарием/revision, парой endpoints, статусом, file tree/progress, попытками/evidence, доступными командами.
- Нажатие на Connection → `ConnectionInspector` с capabilities, quota freshness, operations; редактирование профиля — явная кнопка «Настроить», открывающая окно настроек **в нужном контексте**.
- Нажатие на conflict/needs consent → контекстная панель последствий и решение. До реального Core Policy интерфейс read-only и действие disabled.
- Нажатие на Scenario → краткие сведения и статус текущих задач; кнопка «Настроить сценарий» открывает настройки конкретного ID.
- Глобальный filter popover → connection/scenario/worker. Выбор события устанавливает shared context только для подписанных на него виджетов. У каждого локальное «Переопределено» + «Вернуться к общему».
- Кнопка «+ Виджет» доступна лишь в layout mode; каталог временный drawer/popover и закрывается после добавления/выхода. В monitoring mode верхние действия только Filter, Refresh, Layout, Window, актуальный health.

## 5. Поведение при рисках

**Attention widget:** карточка содержит число и одну наиболее опасную проблему. При отсутствии виджета глобальный индикатор в title/statusbar остаётся. Критическое уведомление не исчезает при фильтре другого Worker.

**UNKNOWN:** отдельная метка «Результат неизвестен», доступна подробная read-only reconciliation; не кнопка «Повторить» без сведений, что операция не совершилась.

**Content download consent:** показывает источник, назначение «основной MacBook», файлы/набор, объём когда известен, почему нужен download и scope права. По умолчанию — отказ; отсутствие реакции не подтверждает загрузку. Не считать системный iCloud download частью согласия QADREN.

**Опасное удаление/overwrite:** полный путь, счётчики и последствия, никакой массовой кнопки без политики. Отдельно показывать факт использования корзины провайдера, если подтверждён API.

## 6. Widget-by-widget первые визуальные варианты

| Виджет | Compact | Regular | Expanded |
|---|---|---|---|
| System | status + source/lastSeen | статус службы + Worker + last refresh | модули + provenance |
| ActiveJobs | count и 1 текущий | 2–3 операции, progress/files/bytes | lazy список и current file tree |
| Queue | active/waiting/unknown counters | 4–6 rows, badges | выбор, приоритет, pause/resume |
| Attention | count + severity | top conflict + action «Подробнее» | решения, ошибки, список ожидающих подтверждений |
| Connections | 1 selected + availability | 2–4 строки quota/status | paths, quotas/limits, adapter capabilities |
| Resources | 2–3 фактические метрики | CPU/RAM/disk + timestamp | telemetry, только если измеряется |
| UpcomingRuns | 1 ближайший запуск | 3–5 schedule rows | timezone, trigger status |
| Timeline | последний event | последние 4–8 | lazy timeline с context filters |

Не ухудшать индикацию критических статусов в compact; если весь текст не помещается, оставлять значок+доступное имя, а подробности в inspector.

## 7. Спецификация режимов

**Monitoring:** layout fixed; data may refresh; view interactions active; никакого edit grid.  
**Editing:** сетка пунктиром, snap, move/resize handles, catalog searchable by widget name, remove/undo, save-after-each-valid-step. Введение режима не останавливает Jobs, не меняет сценарии.  
**Expanded widget:** расширение в пределах рабочей области или отдельном окне; состояние исходной панели и scroll сохраняется. При возврате фокус к исходному виджету.  
**Offline/read-only:** stale data помечены, no live claim; недоступные команды disabled.

## 8. Управление из macOS MenuBarExtra

Меню должно быстро сообщать health и реальные значения active/waiting/attention, дать открытие/создание панели и настройку, паузу Worker (если Core может), явную остановку службы с предупреждением. **Выход из UI не равно остановке службы** в целевой архитектуре; пока служба ещё не вынесена, показывать реальное поведение и не обещать непрерывного исполнения. Не выдавать `NSApp.terminate` за остановку службы.

## 9. UI acceptance

- 1180×760 и 900×620: нет sidebar, overflow/overlay и потери critical indicators.
- Два окна: разные layouts/filters, одна общая Core job truth, никаких дублирующих исполнений.
- Monitoring/edit switch: no dirty layout loss, no widget duplicates in one panel, undo/redo и recovery.
- 0 jobs, many jobs, auth failure, offline, unknown, consent, conflict: верная семантика, нет фальшивых чисел/ETA.
- No focus loss on refresh; keyboard, VoiceOver, contrast, Reduced Motion проверены.
