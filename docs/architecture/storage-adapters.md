# Адаптеры хранилищ

Статус: **модель принята**. Сейчас активно разрабатывается Local Filesystem; Яндекс Диск заморожен до самого последнего P3, его код сохраняется; iCloud — future-only на неопределённый срок (D-018). Метаданные Яндекс Диска и macOS UI исторически проверены (Issue #2, PR #4/#9); контентный E2E ещё не доказан.

## Тип адаптера ≠ экземпляр подключения

Любой адаптер может обслуживать множество независимых `StorageConnection`: в том числе разные аккаунты одного провайдера или повторные подключения одного аккаунта. Тип адаптера не хранит глобальный токен/статус конкретного пользователя; каждый экземпляр имеет собственный ID, настройки, Keychain credentials, ошибки и независимую жизненную историю. Применимые технические ограничения Apple ID и конкретной платформы должны отражаться через capabilities. Подробно: [D-016](../decisions/D-016-multiple-connections.md).

## Контракт возможностей

Каждый адаптер сообщает:
- поддерживаемые ОС и необходимые права;
- доступность метаданных без загрузки содержимого;
- чтение и запись содержимого;
- возможность потоковой передачи;
- подтверждения завершённости удалённой записи;
- доступные идентификаторы версий и контрольные суммы;
- возможности перечисления изменений, удаления, восстановления.

Планировщик не должен строить задание на неподтверждённой функции адаптера.

## Предварительный Rust-контракт (Issue #14)

В `core/src/capabilities.rs` выделено декларативное описание возможностей `CapabilityDeclaration`, `Operations`, `Platform` и `RequestedOperation`. Эта модель предназначена для проверки совместимости и не является разрешением на выполнение I/O: адаптер обязан повторно проверить полномочия, фактическую доступность объекта, а для главного MacBook — согласие на загрузку содержимого непосредственно перед операцией.

Текущие флаги не доказывают реализацию контентных API или подтверждение cloud commit. Их детализация, ошибки, полнота capabilities и совместимость FFI будут продолжены в #14. Не путать `prerequisites_verified` со стабильным разрешением: фактическое состояние может измениться после проверки.


## Яндекс Диск

Реализованы OAuth Authorization Code + PKCE, независимые Keychain credentials на `connection_id`, чтение quota и первой страницы каталога через GET Disk REST API без получения байтов файлов. Обработаны статусы 401/403/404/429/5xx и сетевые ошибки; автоматическое повторение выключено, Refresh — по требованию пользователя. Mock HTTP тесты включают 200/401/403/429/503/timeout; на реальном Mac проверены два аккаунта и независимое отключение. Поведение по большим файлам, лимитам API, контрольным суммам, докачке и live загрузкам **не проверено E2E**; частичный streaming upload код существует, но полный перенос файлов не принят. Не считать server-to-server copy доступной без проверки.

## iCloud Documents — отложено (D-017)

**Не часть Release 1.** Не разрабатывать sync/backup, собственный Documents container, adapter, entitlements, native spike, UI подключения или интеграционные тесты. Историческая идея ограничивалась собственным видимым контейнером, а не произвольным доступом к iCloud Drive/CloudKit. Прежние архитектурные предположения не означают действующих capabilities. Вернуться только по отдельному решению о цене, доступе и Apple APIs. [D-017](../decisions/D-017-defer-icloud.md).

Нативные проверки File Provider/iCloud placeholder при работе **локального** адаптера сохраняются: они запрещают скрытую материализацию и не создают iCloud adapter.

## Local Filesystem

Самостоятельный активно разрабатываемый адаптер локальных файловых систем и каталогов. **Не часть iCloud Documents** и не способ скрытого доступа ко всему iCloud Drive. Перед чтением файла в iCloud-управляемом каталоге необходимо определить, не инициирует ли операция запрещённую материализацию содержимого на основном MacBook.

## Новые адаптеры

Интеграции новых облаков и серверов добавляются независимо от ядра; macOS-зависимость iCloud не переносится на весь QADREN.
