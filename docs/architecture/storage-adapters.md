# Адаптеры хранилищ

Статус: **модель принята**. Яндекс Диск: реализован и вручную проверен metadata-only адаптер и macOS UI (Issue #2, PR #4/#9); остальные адаптеры пока не реализованы.

## Тип адаптера ≠ экземпляр подключения

Любой адаптер может обслуживать множество независимых `StorageConnection`: в том числе разные аккаунты одного провайдера или повторные подключения одного аккаунта. Тип адаптера не хранит глобальный токен/статус конкретного пользователя; каждый экземпляр имеет собственный ID, настройки, Keychain credentials, ошибки и независимую жизненную историю. Применимые технические ограничения Apple ID и конкретной платформы должны отражаться через capabilities. Подробно: [D-016](../decisions/D-016-multiple-connections.md).

## Контракт возможностей

Каждый адаптер сообщает:
- поддерживаемые ОС и необходимые права;
- доступность метаданных без загрузки содержимого;
- чтение и запись содержимого;
- возможность потоковой передачи;
- подтверждения завершённости удалённой записи;
- доступные идентификаторы версий и контрольные суммы;
- возможности перечисления изменений, удаления, восстановления.

Планировщик не должен строить задание на неподтверждённой функции адаптера.

## Яндекс Диск

Реализованы OAuth Authorization Code + PKCE, независимые Keychain credentials на `connection_id`, чтение quota и первой страницы каталога через GET Disk REST API без получения байтов файлов. Обработаны статусы 401/403/404/429/5xx и сетевые ошибки; автоматическое повторение выключено, Refresh — по требованию пользователя. Mock HTTP тесты включают 200/401/403/429/503/timeout; на реальном Mac проверены два аккаунта и независимое отключение. Поведение по большим файлам, лимитам API, контрольным суммам, докачке и загрузочным URL **не проверялось**, поскольку контентные операции ещё отсутствуют. Не считать server-to-server copy доступной без проверки.

## iCloud Documents

Выбран **собственный пользовательски видимый iCloud Documents container** с обычными файлами и папками (не CloudKit records). macOS-адаптер работает через официальные механизмы Apple.

Ограничения:
- создание собственного контейнера не предоставляет универсальный удалённый REST API;
- файл, записанный локально, не обязательно завершил выгрузку в iCloud;
- чтение отсутствующего локально содержимого может инициировать системную материализацию;
- возможности фонового режима, публикация папки в Finder/Files, entitlement, подтверждения облачной выгрузки и поведение на разных устройствах требуют проверки прототипом.

Доступность собственного контейнера из Finder/Files — **целевое поведение**, подтверждаемое испытаниями на поддерживаемых устройствах и с нужной конфигурацией Apple.

## Новые адаптеры

Интеграции новых облаков и серверов добавляются независимо от ядра; macOS-зависимость iCloud не переносится на весь QADREN.
