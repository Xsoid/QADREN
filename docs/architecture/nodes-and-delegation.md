# Узлы и делегирование

Статус: **принято** на уровне принципов. Протокол взаимодействия **отложен**.

## Термины: источник не равен Controller

`StorageConnection` обозначает подключение к облаку/серверу. В правилах такое подключение выступает **источником** или **назначением** данных. `Controller` и `Worker` — роли **узлов QADREN**, не хранилищ. Каждый адаптер может иметь неограниченное количество экземпляров подключения; узел обрабатывает только явно разрешённые ему подключения. Ключи авторизации одного Worker не передаются Controller автоматически (см. [D-016](../decisions/D-016-multiple-connections.md)).

## Одна программа — разные роли

- **Controller** формирует правила, назначает задания, получает отчёты и показывает статус.
- **Worker** выполняет работу с файлами и облаками.
- Экземпляр может совмещать роли. Подчинённый Mac может запускать ту же программу, что главный.
- Главный MacBook не обязан иметь доступ к содержимому резервируемых данных.

## Владение заданием

После делегирования назначенный Worker — **единственный исполнитель** данного задания. Controller:
- не начинает параллельную передачу;
- не скачивает файл для проверки делегированной задачи;
- не выполняет повторную попытку вместо Worker без отдельного явного процесса перепоручения;
- принимает, сохраняет и отображает отчёт Worker.

При потере связи нельзя считать задачу неисполненной: состояние должно отражать неопределённость (например, `UNKNOWN`), а повторную передачу необходимо проектировать идемпотентно.

## Отчёты

Отчёт должен различать заявление Worker «успешно», подтверждение удалённого сервиса и подтверждённую проверку целостности. Данные отчёта могут включать ID задания, идентификатор версии, источник и назначение, результат, признаки завершения записи, хеш/размер, ошибки и время. Точная схема пока не определена.

## Автономность

После получения полномочий и правил Worker должен иметь возможность исполнять допустимые задания при выключенном Controller. Это **целевая возможность**, её конкретная реализация зависит от механизма связи и прав.

## Не проектируем сейчас

Обнаружение, пары и доверие между узлами, транспорт, аутентификацию, распределённую блокировку, синхронизацию журналов, отзыв делегирования, политику выбора нового Worker. До реализации эти вопросы необходимо закрыть отдельно.
